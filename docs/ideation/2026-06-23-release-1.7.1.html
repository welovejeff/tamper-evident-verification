Codebase Context

Tamper Signal (v1.7.0) signs a receipt on every stage of a data pipeline; receipts verify collapses the chain to a traffic light: green intact, yellow asks for eyes, red broken at a named link with a totals delta. Two stacks produce interchangeable chains: Python (tamper-signal on PyPI) and Node (tamper-signal on npm), kept byte-identical by golden vectors. The honest claim is fixed: it proves continuity, not correctness. The CLI surface is mature: keygen / ingest / verify / init / doctor / export / diff / log / anchor / serve / demo. There are zero open GitHub issues and the codebase carries almost no TODO/FIXME debt.

The signal for a point release does not come from a backlog. It comes from three places: the two bugs that escaped the green suite and reached users, the items the maintainer explicitly deferred in the CHANGELOG, and the rough edges of what 1.7.0 just shipped.

The two bugs that motivate the top tier

  • Browser ZIP writer drift (docs/solutions/.../browser-zip-writer-drift-no-parity-test.md): the inline ZIP writer in badge/table.js drifted from the canonical node/zip.js and shipped a malformed 0000-00-00 bundle timestamp. npm test stayed green because the inline copy has no test. The fix added a byte-parity test; the lesson is that other hand-duplicated browser logic still has none.
  • Sigstore OIDC issuer mismatch (docs/solutions/.../sigstore-federated-oidc-issuer-certificate-mismatch.md): every browser-login anchor failed its own verify, because the stored issuer was the token's and the verifier compares the certificate's. 83 Python + 28 Node tests passed throughout; the test boundary was monkeypatched, so no test exercised a real Fulcio cert. Only a live staging smoke test caught it.

Both are already fixed. Both reveal the same systemic gap: the suite is green on paths it never exercises. That gap, not the individual bugs, is the strongest thing a 1.7.1 can close.

01

Byte-parity tests for the hand-duplicated browser logic

Lead
confidence: high complexity: low–med basis: badge/badge.js
What it is

Extend the byte-parity discipline the zip fix introduced to the other logic hand-duplicated into badge/badge.js: totalsDelta (the badge copy lacks the Decimal arithmetic of node/totals.js), the receipt-field accessors (outputHashOf/inputHashOf/totalsOf/stageNameOf, hardened in node/receipts.js but bare in the badge), and the three-way trusted-key normalization shared by Python, node, and the badge. Each gets a node --test that slices the inline block out of the source, imports it via a data: URL, and asserts byte-identical output to the canonical copy for degenerate inputs.

Basis

badge/badge.js:65–104 (accessors + totalsDelta), badge/badge.js:198 (key-norm), node/receipts.js:262 ("update all three in lockstep" comment), pattern from node/test/zip.test.js.

Why it leads 1.7.1

This is the exact prevention the zip-drift learning doc asks for, generalized: "any logic hand-duplicated across the node/ and browser trees needs a byte-parity test." The comment admitting the duplication is unfenced is still load-bearing. This is the cheapest insurance against the next bundle that ships wrong to a stranger.

Adversarial note

Risk is doing this once and calling the axis closed. The deliverable is a reusable harness (source-slice + data: import) so the fourth copy added later is cheap to pin, plus a one-line rule in AGENTS.md.

02

Close the test blind spots, add the two release gates

confidence: high complexity: med basis: anchor.py / release.yml
What it is

A small bundle of targeted guards for the paths the green suite never exercised. (a) Unit-test _certificate_issuer's fallback directly: an unknown Fulcio OID must return None, not a wrong value, and the V2 extension must win over the legacy one when both are present. (b) Add the reverse interop test — a node-signed chain verified by the Python CLI end to end, not just Python→node plus golden vectors. (c) A loader-enumeration guard that fails the suite when a new load_* is added to canonical.py without joining the cross-format identical-hash test. (d) A named static-sync step in release.yml before publish, so a missed cp during a hotfix fails loudly at the gate. (e) A documented (not-CI) scripts/smoke_anchor_staging.sh for the interactive anchor round-trip.

Basis

tamper_signal/anchor.py:78–91 (broad except → silent fallback), node/test/interop.test.js:22–43 (one-directional), tests/test_integrations.py (sync guard buried in the matrix), the sigstore doc's "run a live round-trip smoke test for every IdP path before release."

Why 1.7.1

Each item is the literal "Prevention" bullet from one of the two learning docs, none of which produced an artifact you can run. They are individually tiny; together they convert "we know the lesson" into "the suite enforces it."

Adversarial note

The smoke script can't run in CI (browser OIDC), so its value depends on a human actually running it pre-release. Pair it with a release-checklist line so it is not optional-by-forgetting.

03

Stop mis-blaming ingest --as period when no chain exists

confidence: high complexity: low basis: wrapper.py:227
What it is

Continuing a period chain that does not exist yet raises UntrustedSignerError, and the CLI prints the "Refusing to append a period" trust preamble. But a missing chain.json is not a trust problem — it is "start a chain first." Re-map that condition to a usage error (ValueError or a dedicated subclass) with a message that points at ingest --as replace.

Basis

tamper_signal/wrapper.py:227–230 (raise site), tamper_signal/cli.py:184–186 (catch + preamble).

Why 1.7.1

The product's honesty rule is that yellow asks for eyes and never blames; a red trust accusation for a first-run usage mistake is the same category error pointed at the user. One raise site, one catch clause, no exit-code or behavior change.

04

Make silent numeric normalization visible

confidence: high complexity: low–med basis: canonical.py + node/cli.js
What it is

Canonicalization silently coerces numeric-looking text: "030" and "30.00" hash as 30, so leading zeros and trailing decimals die on a round trip and the light stays green. Separately, grouped numbers like "289,084" are excluded from numeric_sums — and the node CLI already warns about this while the Python CLI says nothing (a one-stack asymmetry). Fix the whole story: a pre-scan at ingest that names affected columns in a warnings list (visible in --json and stderr), reaching parity with node; plus a one-sentence caveat in export output and the browser download note.

Basis

tamper_signal/canonical.py:72,164–165 (coercion site), node/cli.js:316–325 (warning the Python side lacks at cli.py:257–272), tests/test_portability_integrity.py:77–83 (the round-trip is tested but never surfaced to the user).

Why 1.7.1

A green light over a value that quietly changed is the precise thing this product exists to prevent. The behavior is correct and documented; the gap is that the person clicking Download is never told. Additive output only, and it closes a real cross-stack inconsistency.

05

verify names a transforms-only chain instead of implying full coverage

confidence: medium complexity: low basis: cli.py:470
What it is

A chain that holds only a source manifest and no @receipt_step stages verifies green with no hint that it covers the ingest but none of the transforms. Add a caveat (or stderr notice) when transforms == 0 that names the gap, without changing the green verdict — the same "ask for eyes" posture yellow already takes.

Basis

tamper_signal/cli.py:470–474 — the --json payload already emits "stages": ["source"] and "transforms": 0; the data to detect the gap is in scope.

Why 1.7.1

This is the prior doc's "name the missing stage" reject, now concretely sized at ~3 lines. A producer who forgot to wrap their pipeline gets a falsely reassuring green; naming it is squarely the product's job.

Adversarial note

Decide deliberately: a source-only chain is a legitimate use (attesting a dataset with no transforms). So this is a notice, not a yellow trip — tripping yellow would punish a valid pattern and erode trust in the light.

06

Finish the --json surface: ingest, export, doctor

confidence: high complexity: low basis: cli.py (3 cmds)
What it is

verify and anchor emit --json; ingest, export, and doctor still print only human text, so an agent or CI loop must scrape. Add --json to all three. The payloads already exist as local variables: doctor holds checks: list[tuple[name, ok, fix]] + warns; ingest has result["manifest"] (semantic hash, row/column counts, tolerance); export has the path, row count, and data hash. While here, add the declared band/settle_hours to log --json, which already has the snapshots in hand.

Basis

tamper_signal/cli.py:583–695 (doctor), cli.py:216–272 (ingest), cli.py:756–798 (export), cli.py:1344–1362 (log json), pattern from cli.py:1564 (verify --json).

Why 1.7.1

AGENTS.md sells an agent-native workflow but the JSON surface is half-built. Any action a human takes at the CLI an agent should take structurally — this is the parity gap, and the data is already assembled at each site.

07

Unify and document the exit-code contract

confidence: medium complexity: low basis: cli.py (3 cmds)
What it is

verify advertises the traffic light as exit codes 0/1/2; the rest are inconsistent. ingest --as period can exit 2 (yellow) but never says so in its help. diff exits 0 whether runs are identical or wildly different. doctor exits 0 even with warnings, so an agent can't tell "clean" from "clean with warnings." Document the ingest exit contract in help, give doctor a warnings-only exit 2, and add an opt-in --exit-on-diff to diff (opt-in to avoid breaking if receipts diff; then callers).

Basis

tamper_signal/cli.py:1527–1533 (ingest help, no exit note), cli.py:694–695 (doctor returns 0/1 only), cmd_diff return path (always 0 on valid compare).

Why 1.7.1

The traffic-light exit convention is a selling point; it should hold across every command an agent scripts. Mostly one-line changes plus help text.

Adversarial note

Changing diff's default exit would silently break existing pipelines — hence opt-in. The doctor warnings-only→2 change is safe because the common all-clean path stays 0.

08

receipts suggest-bands — read-only band advisor

confidence: medium complexity: med basis: CHANGELOG 1.6.0
What it is

A pure-read command that scans receipts/history/ via the existing load_snapshots and reports, per metric, the observed max period-over-period movement, then prints suggested --band / --settle values a producer can paste into their next ingest. No writes, no signatures, no verdict change.

Basis

CHANGELOG 1.6.0, "Deferred: a suggest-bands helper." Math mirrors the existing history.py:660–818 judgment arithmetic; no line of it exists yet.

Why 1.7.1

The strongest new-capability candidate: the maintainer named it, it is read-only (~30 lines over already-tested primitives), and it removes the main friction in adopting tolerance bands — guessing the numbers. The only open call is output shape (human text vs --json; do both).

09

--history-keep N retention pruning

confidence: medium complexity: low basis: CHANGELOG 1.6.0
What it is

Every non-red verify archives a snapshot to receipts/history/ with no cap, so a scheduled pipeline grows unbounded. Add --history-keep N (or a project config field) that, after judgment completes, unlinks the oldest snapshots beyond N. Content-addressed filenames sorted by created_at make the delete trivially safe.

Basis

CHANGELOG 1.6.0, "Deferred: history retention/pruning." Hook point is cli.py:289 (_archive_after_verify, already called after judgment); implementation is a sorted-delete in history.py.

Why 1.7.1

The one operational pain a real scheduled user hits, with a safe and contained fix. Prune strictly after judgment so an in-flight cross-run comparison never loses a snapshot it was about to read.

10

Bundle recipient on-ramp: filename, dual-stack, ingest path

confidence: medium complexity: low basis: cli.py + badge/table.js
What it is

A cluster of small fixes to the 1.7.0 bundle for its actual purpose — being sent to a stranger. The bundled README.md tells the recipient to receipts verify chain.json but never how to bring the data into their own chain with ingest --as period; add that section. The browser export hardcodes the data file as data.<ext>, so a recipient who wants to ingest must guess the name — embed the original filename from the chain's source manifest instead. And the export stdout names only the Python command; mirror the README's dual-stack (pip / npm) wording.

Basis

tamper_signal/cli.py:61–88 (bundle README constant), cli.py:834 (Python-only stdout), badge/table.js:374–386 (hardcoded data.<ext>), mirrored in badge/table.js:251–277.

Why 1.7.1

1.7.0's headline is "take your data out and bring it back," but the recipient's round trip has dead ends. These are doc-text and one-line filename changes with zero protocol risk.

11

Bundle robustness: clobber guard + readable browser errors

confidence: medium complexity: low basis: cli.py:820 + table.js:388
What it is

Two small hardening fixes. export --bundle writes <stem>-verified.zip unconditionally, silently replacing a bundle a recipient may already hold a hash for; add an "exists, pass --out or --force" guard. And the browser download handler swallows every fetch failure into "Could not build the download. Try again." — log the real error and include its message, so a CORS failure or a 404 on a receipt is diagnosable without DevTools.

Basis

tamper_signal/cli.py:820 (unconditional write), badge/table.js:388–390 (unused caught error _e).

Why 1.7.1

For a tool whose entire premise is an audit trail, silently overwriting an attested artifact is the wrong default; and opaque browser errors make self-hosters file bugs that a logged message would have answered. Both are one-liners.

12

A delightful, colorful CLI — the traffic light made literal

User pick
confidence: medium complexity: med basis: cli.py (no color today)
What it is

A small human-facing presentation layer for the receipts / tamper-signal CLI that makes everyday use legible and genuinely pleasant: the verdict rendered as a colored ● light (green / amber / red) that matches the exit code and the words; dimmed hashes and aligned label columns so output scans at a glance; a confident one-line summary above the quiet detail; and the diff / totals deltas shown with red-down / green-up coloring where the eye most wants it. A first-run flourish on init and demo (a tasteful banner), not on every command.

Basis

tamper_signal/cli.py uses plain print() with ✓/✗ glyphs and zero color (no isatty/NO_COLOR/ANSI anywhere today). Deps are only openpyxl + cryptography; the node CLI is dependency-free — so the fit is a ~30-line self-contained ANSI helper, not rich/colorama.

Why 1.7.1

It is the first thing every human user sees and it has never had a design pass. It pairs cleanly with #6: humans get the colored light, agents get uncolored --json. No protocol, spec, or receipt-byte change — purely the rendering layer.

The decisions that keep it on-brand (not slop)

Color is redundant, never the only signal. The verdict word and glyph remain, so colorblind users, NO_COLOR, and piped output lose no information. Gate hard: emit ANSI only when stdout.isatty(), honor NO_COLOR / FORCE_COLOR and a --no-color flag, and never colorize --json or anything redirected to a file. Restraint over confetti: this is a trust tool — red stays grave and precise, yellow still only asks for eyes; no emoji spray, no fake spinners. Cross-stack parity: same palette and gating in node so the two CLIs read as one product (a presentation sibling of the dual-tree parity work in #1).

Adversarial note

The failure mode is decoration that undercuts gravity, or ANSI bytes leaking into a machine-read stream and corrupting a hash comparison or a CI parser. Both are designed out by the gating rules above; a snapshot test that asserts no ANSI escapes appear under --json or a non-TTY pipe makes it enforceable. Scope risk: a full TUI is 1.8.0+; this is strictly the static-output rendering layer.
